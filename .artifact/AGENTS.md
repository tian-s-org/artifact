# 画布写作规范（给 Agent）

这份画布是 artifact 自己的原型。下面的约定来自线上查看器的实现，**画框标签由底座渲染，画板里不要自己画标题**。

## 先看这里：哪些别动

| 东西 | 谁维护 | 说明 |
| --- | --- | --- |
| `.canvas` | CLI | 画布 id 绑定，`push` 自动写。别改、别删——删了下次 push 会新建一块画布，旧链接还在但对不上内容。 |
| `layout.json` 的 `protocol` | 协议 | 固定 `1`，别动。 |
| 画框 `id` 与目录名 | 你 | 要改就两边一起改：`layout.json` 的 `id` 和 `artboards/<id>/` 必须一致。 |
| `assets/css/` 共享样式 | 你 | 能改，但一改所有画框都变；先确认影响面。 |
| 画板里的脚本、外网资源 | 沙箱 | 不是建议是硬约束：`sandbox=""` 不执行脚本，CSP 不放行外网。 |

**你该动的地方只有**：`layout.json` 的 `boards`、`artboards/`、`assets/`、`context.md`。

## 画框标题与序号（Figma 式）

- 标签格式：**`01 技能库`** —— 两位序号 + 一个空格 + 名称。
- 字号：**12.5px，固定屏幕大小**。底座会把标签按 `1 / 缩放` 反向缩放，所以 24% 和 200% 下都一样大；
  画板里不要为了「看得清」自己放大字号。
- 序号 = `layout.json` 里按 `order` 排完后的位置（01、02…）。新增画框时把它插到正确的地方，
  而不是追加到末尾了事。
- 名称：2–6 个字的名词短语，画什么写什么（技能库 / 同步矩阵 / 设置）。同一组方案可以用「方案 A / 方案 B」。
- 名称里不要写尺寸、版本、编号：尺寸由悬停标签显示成 **`01 技能库 · 1440 × 900`**。
- 不要用 `Frame 1`、`未命名`、`board-001` 当显示名。`id` 只用于目录名与深链 `?focus=<id>`。
- 画板内部不要再写一遍大标题来充当序号；画框内容直接从界面元素开始。

## 画框尺寸

- 同一块画布里默认**统一尺寸**（桌面端用 `1440 × 900`），视觉上才整齐、比较才成立。
- 只有「设计本身针对不同设备」时才用不同尺寸，并在名称里标出来：`01 手机首页 · 390×844`。
- 不要为了内容多少临时改尺寸；内容多就排版收一点，不要改画框。

## 摆位

- 主流程从左到右、从上到下；同一组方案相邻，间隔 160px 以上，不重叠。
- 画布无限大，多屏就多开画框；不要为了「省地方」把两块塞进一个画框。

## 视觉

- 颜色、字号、圆角只取 `assets/css/` 里的令牌，画板不另造一套。
- 画板是静态 HTML：无脚本、不引外网、资源用相对路径。
- 放大要清楚：矢量 SVG、真文本、1px 边框。

## 自检

改完先在本机看一遍：`node skills/.../validate.mjs .artifact`（校验 layout.json 与文件），
再 `artifact push .artifact`，刷新链接确认标签字号与序号。
