# 内容平台架构

给一家中型内容团队做内部平台：收信、会话、全文检索、实时推送。日活 3 万，日消息 120 万条。
这一轮不是选框架，是让工程和运营一起看懂两个候选形态差在哪、要付什么代价。

## 这一轮看什么

- 方案 A（模块化单体）与方案 B（拆分服务）并排比较：写路径、扩展方式、运维成本。
- 请求时序：一封信从 IMAP 拉取到推给客户端，经过哪些环节、哪个环节会先撑不住。
- 部署拓扑：全球 CDN + 单区应用 + 单库主备，瓶颈标出来。

## 约束

- 图全部用 SVG / CSS 画，不用位图截图，放大到 400% 也要清楚。
- 每张画板只讲一件事，结论写一句，别堆满。
- 方案用颜色区分（A 蓝、B 青），风险用橙色标；其它一律黑白灰。
